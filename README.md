# 本地数值作业与结果归档

在本机运行的数值作业归档：接收有符号 64 位整数序列，计算总和与平方和，
支持作业提交、查询、取消、依赖与结果持久化。

## 能力

- **提交**：记录提交人、幂等请求号、整数序列与种子，接受后返回稳定作业号；
  空序列、引用不存在依赖、依赖列表含零/重复作业号或混用两种依赖方式的提交
  被整体拒绝，不产生记录，也不占用幂等请求号。
- **多依赖**：提交时可给出有顺序的上游作业号列表（`Dependencies`）；只有列表
  中作业全部成功且归档完整后本作业才可运行，各上游总和严格按列表次序逐个
  追加到原始序列末尾（与上游完成先后无关）。例如原始输入 `[10]`、上游总和
  依次为 `3` 与 `-2` 时，实际输入为 `[10,3,-2]`，总和 11、平方和 113。
  列表只能引用提交时已存在的作业；引用已失败/取消的上游仍接受提交，但新作业
  立即失败。原单依赖写法（`HasDependency`+`DependencyID`）继续可用，空列表
  沿用无依赖行为；单依赖与只含同一作业号的列表视为相同提交内容。
- **计算**：输出总和与平方和；结果超出 int64 范围时作业失败并说明原因，
  不留下成功结果。依赖作业成功归档后，其总和作为额外整数追加到本次输入末尾。
- **调度**：本地一次只运行一个作业，其余可运行作业严格按提交先后执行；
  等待依赖结果的作业会被跳过，不挡住后面可运行的作业。任一上游失败或取消时
  不必等待其余上游，本作业及下游立即失败；多个直接上游阻断时取列表最靠前者，
  原因指出该直接上游与阻断链条的根因作业号，之后的上游状态变化不改写原因。
  排队详情（`PendingDependencies`）按提交次序列出尚未成功归档的直接上游，
  全部可用后排队原因转为等待计算位置。
- **状态**：区分排队（等待计算位置 / 等待依赖结果）、运行、成功、失败、取消；
  依赖失败或取消会沿链条级联，失败信息指出阻断它的作业与根因。
- **幂等**：请求号在同一提交人内有效；同人同号同内容（整数次序、种子、依赖
  列表的内容与次序）返回原作业，任一变化返回冲突并保留原记录；并发重复提交
  只建一个作业。
- **取消**：排队与运行中的作业可取消，取消合并作业只影响它自己与下游，不取消
  其余上游；取消后该作业及下游不再产生成功归档；重复取消已取消作业仍成功，
  取消已成功/失败作业返回不能取消且原结果不变。
- **归档**：成功记录保存原始参数、依赖顺序、实际参与计算的输入摘要、结果摘要、
  计算日志与校验值；相同有效输入与种子得到相同结果摘要、日志与校验值
  （作业号、时间与上游作业号不参与）。成功状态与完整归档在同一次原子写入中可见。
- **查询**：按作业号读取详情，或按提交人与提交时间范围（两端包含）列举，
  起始晚于结束拒绝，结果按提交先后排列；返回数据为拷贝，外部修改不影响记录。
- **持久化**：重新打开目录后，提交、多依赖关系、取消与完成结果不丢失，
  幂等号继续生效，排队作业按恢复后的上游状态继续等待、执行或失败；上次关闭时
  仍在运行的作业标记为失败（计算被中断）并继续阻断未结束的下游。旧格式记录
  仍可读取，已有成功归档的摘要与校验值不因升级而改变。

## 使用

```go
store, err := numeric.Open("/path/to/archive")
if err != nil { ... }
defer store.Close()

job, err := store.Submit(numeric.SubmitRequest{
    Submitter: "alice",
    RequestID: "req-001",
    Values:    []int64{1, 2, 3, 4},
    Seed:      42,
})
// ...
detail, err := store.Get(job.ID)
if detail.Status == numeric.StatusSucceeded {
    fmt.Println(detail.Archive.Sum, detail.Archive.SumOfSquares)
}
```
